# PROMPT START

## 0. ROLE AND MISSION

Act as a Senior Frontend Engineer, Senior UI/UX Designer, and Frontend Architect working as one person.

Build the **complete frontend** of **NutriSense**, "An Explainable, Multimodal Nutrition Companion for Real-World Indian Eating", for a hackathon.

The product answers one question: **"What should I eat next, based on what I have already eaten?"**

Core loop:
`FOOD INPUT → FOOD UNDERSTANDING → NUTRITION ESTIMATE → DAILY LOG → NUTRIENT GAP → PERSONALIZED, EXPLAINED RECOMMENDATION`

Input methods: dish photo, restaurant menu photo, food-delivery screenshot, voice, manual search, and an optional health/lab report.

The product must feel like decision support and nutrient balance for Indian food, not a calorie counter. When someone opens it, they should think: *"This understands what I'm trying to eat, not just what I ate."*

## 1. SCOPE

**Build now:** the full working frontend, with a clean service layer running on mock implementations.

**Do NOT build now:** backend, database, ML/DL models, OCR engine, speech model, recommendation engine, medical analysis. Only prepare clean integration boundaries so the backend, DL, OCR and speech services plug in later without touching the UI.

## 2. NON-NEGOTIABLES

1. **One responsive web app, one deployed URL**, usable on desktop, laptop, tablet, Android and iPhone, from 320px to ultra-wide. No separate mobile project and no React Native.
2. **PWA-ready** (installable from the same URL).
3. **No green mascot.** Do not reuse or imitate the green creature in the reference images. Use the original **NutriMotes** system (section 7).
4. **Animated splash of exactly ~5 seconds with a "Skip" button** in the top-right, visible for the whole animation (section 8).
5. **Every step in the reference images exists** as a working screen (section 10). Do not merge or omit screens that look similar.
6. **Login / Register / Forgot Password / Logout** using Firebase Authentication, with **Demo Mode** fallback when env vars are missing.
7. **`.env.example` exists and real `.env` files are git-ignored.** No secrets in code.
8. **Components never import mock data.** Only `services/` may import from `mocks/` (enforce with an ESLint `no-restricted-imports` rule).
9. **Every recommendation shows "why it was recommended"** and uses estimate ranges, never false precision.
10. **Not green-dominant, not template-looking, not a phone mock centered on a desktop screen.**

## 3. TECH STACK (locked — don't debate)

React 18 + TypeScript (strict) + Vite + Tailwind CSS + React Router v6 + Framer Motion + Firebase Auth (modular SDK) + lucide-react + `vite-plugin-pwa` + `@fontsource` (self-hosted fonts).

- State: React Context + `useReducer`, persisted to `localStorage` (versioned key, e.g. `nutrisense:v1:*`). No Redux.
- Charts and rings: hand-built SVG components. No chart library.
- Animation: Framer Motion, CSS and SVG only. No video and no heavy Lottie files.
- No `any`. Routes lazy-loaded with `React.lazy` + `Suspense`.
- Scripts: `dev`, `build` (`tsc -b && vite build`), `preview`, `typecheck`, `lint`.

## 5. API-READY SERVICE LAYER

Data flow today: `Component → hook → service → mock`. Later: `Component → hook → service → backend`. The UI never changes.

**Rules**
- Every service function returns `Promise<T>` with typed input and output.
- Each service has a single switch: `USE_MOCK` from `VITE_USE_MOCK_API` (default `true`). The mock branch lives inside the service. The real branch calls `api.ts`.
- `api.ts` provides one `request<T>()` wrapper: base URL from `VITE_API_BASE_URL`, attaches the Firebase ID token, 20s timeout, supports `FormData` for uploads and normalizes errors into `AppError { code, message, recoverable, action }`.
- Error codes: `NETWORK`, `UNAUTHORIZED`, `FILE_TOO_LARGE`, `UNSUPPORTED_FORMAT`, `IMAGE_UNPROCESSABLE`, `LOW_CONFIDENCE`, `NO_TEXT_DETECTED`, `SERVICE_UNAVAILABLE`.
- Mocks simulate realistic latency (600–1800ms) and can simulate errors through a dev toggle (Settings → Developer, visible in Demo Mode only).
- Add `// TODO(BACKEND|DL|OCR|SPEECH|RECOMMENDATION): …` comments **only** at these boundaries. Never scatter TODOs elsewhere.

**Endpoint map to prepare (interfaces only, do not implement a backend)**

| Service | Function | Endpoint | Integration tag |
|---|---|---|---|
| auth | login / register / logout / reset | `POST /auth/login`, `POST /auth/register` (Firebase for now) | BACKEND |
| profile | get / update | `GET /profile`, `PUT /profile` | BACKEND |
| food | analyzeImage(file) → `FoodCandidate[]` | `POST /food/image/analyze` | DL |
| food | search(q) | `GET /foods/search?q=` | BACKEND |
| food | getNutrition(id) | `GET /foods/:id/nutrition` | BACKEND |
| nutrition | calculate(items, portions) | `POST /nutrition/calculate` | BACKEND |
| nutrition | logMeal / todayMeals | `POST /meals`, `GET /meals/today` | BACKEND |
| nutrition | dailySummary / weeklySummary | `GET /nutrition/daily-summary`, `GET /nutrition/weekly-summary` | BACKEND |
| ocr | menu(file) → `OCRResult` | `POST /ocr/menu` | OCR |
| ocr | deliveryScreenshot(file) | `POST /ocr/delivery-screenshot` | OCR |
| speech | transcribe(audioBlob) → `SpeechResult` | `POST /speech/transcribe` | SPEECH |
| recommendation | recommend(context) | `POST /recommendations` | RECOMMENDATION |
| report | analyze(file) → `LabReport` | `POST /reports/analyze` | BACKEND |
| assistant | chat(message, context) | `POST /assistant/chat` | BACKEND |

**Types** (in `types/`, no `any`): `User`, `UserProfile`, `NutritionGoal`, `Food`, `FoodAlias`, `FoodCandidate` (id, name, confidence 0–1), `Meal`, `MealItem`, `Portion`, `NutritionRange` (`{min, max, unit}`), `MacroNutrients`, `MicroNutrients`, `DailyNutritionSummary`, `WeeklyNutritionSummary`, `NutrientGap`, `Recommendation` (includes `reasons: Reason[]` where each reason has `key`, `label`, `passed`, `profileField?`), `MenuItem`, `OCRResult`, `SpeechResult`, `LabReport`, `Achievement`, `AppError`.

Confidence bands: **High ≥ 0.80, Medium 0.50–0.79, Low < 0.50**. If the top dish prediction is below 0.60, show a "We're not sure" state that offers Choose Another Dish and Search Manually.

## 6. AUTH, DEMO MODE, ENV

- `config/firebase.ts` initializes Firebase **only** from `import.meta.env.VITE_FIREBASE_*`. `config/env.ts` validates the env and exposes `isFirebaseConfigured`.
- `auth.service.ts` defines an `AuthService` interface with two implementations: `FirebaseAuthService` (email/password, Google Sign-In, reset email, `onAuthStateChanged`) and `DemoAuthService` (localStorage). The factory picks one automatically. A discreet "Demo Mode" badge is shown when Firebase is not configured.
- Login screen: email + password, "Continue with Google" (enabled only when Firebase is configured), and **"Try the demo instantly"**, a one-tap guest login for judges.
- Friendly mapping for Firebase errors (wrong password, user not found, email in use, weak password, network, too many requests), each with a recovery action.
- Post-auth routing: new user → `/onboarding`; returning user → `/dashboard`. `ProtectedRoute` guards all app routes.

## 8. NUTRIMOTES — ORIGINAL CREATURE SYSTEM

Small **abstract nutrient organisms** built as SVG React components: `<NutriMote type mood size />`. `type` is one of the seven below. `mood` is `idle | curious | happy | celebrating | resting`.

They must feel modern, organic and slightly futuristic. They must not resemble Pokémon, Duolingo, emoji, or any existing mascot. **No limbs, no mouths, no cartoon faces.** At most two tiny dot "eyes" or a single soft glowing core. Character comes from shape, glow, and motion.

| Mote | Design |
|---|---|
| Protein | Linked chain of 3 rounded hexagon beads that flex like a folding chain (green) |
| Iron | Warm rust-orange faceted pebble with a metallic sheen and a slow shimmer |
| Calcium | Pale translucent crystal shard cluster that catches light |
| B12 | Indigo-violet glowing orb with a thin orbiting halo ring |
| Hydration | Transparent droplet with a moving inner ripple |
| Energy | Small amber ember-particle that pulses like a heartbeat |
| Fiber | Abstract fern/leaf spiral (green-teal) |

**Behavior:** gentle idle float (3–5s loops), slow blink or glow pulse. Motes **react to progress**: brighter and closer to the center as their nutrient nears the target, and one short celebration when it hits 100%. They are limited to onboarding, splash, loading/scan states, success states, nutrient cards (small), empty states, streaks, achievement badges, and recommendation explanations. Never a constantly bouncing mascot. Achievement badges are abstract compositions of motes.

## 9. SPLASH SCREEN (~5 seconds, skippable)

Route `/`. Warm dark charcoal canvas that crossfades to cream on exit. Built with SVG + Framer Motion (under about 30KB, no video).

| Time | Beat |
|---|---|
| 0.0–0.8s | One tiny glowing spark fades in at the center |
| 0.8–2.5s | Five motes (Protein, Iron, Calcium, B12, Fiber) enter on curved paths from different edges, orbit and gently attract each other |
| 2.5–3.5s | Motes merge and morph into the NutriSense mark (a leaf with an orbit line) drawn with a stroke-then-fill reveal |
| 3.5–4.3s | Wordmark **NutriSense** fades in letter by letter |
| 4.3–5.0s | Tagline **"Better choices begin with understanding."**, then smooth transition |

- **Skip** button: top-right, always visible (respects safe area), 44px+ target, keyboard focusable, `aria-label="Skip intro"`. It navigates immediately and cancels the timer, and timers are cleaned up on unmount.
- Auto-navigates at ~5000ms. Routing after splash: authenticated + onboarded → `/dashboard`; authenticated, not onboarded → `/onboarding`; otherwise → `/welcome` ("Get Started" / "I already have an account").
- Play once per session (`sessionStorage`). Settings has a "Replay intro" option.
- Reduced motion: no particle travel, a simple logo crossfade, and it still finishes within 5s.

## 10. SIGNATURE INTERACTIONS (what makes it unique)

1. **Nutrient Orbit** (dashboard hero): concentric rings for Protein, Carbs, Fat, Fiber, Iron, Calcium, B12, each with its NutriMote orbiting on its ring. Tapping a ring opens a sheet with the gap, food sources, and a "Find foods" action.
2. **What-if Preview:** "Preview impact" on any recommendation, comparison card or ranked menu item animates the rings with a dashed projected fill before the user adds anything.
3. **Range Bars:** uncertainty shown as a translucent band around a point marker, plus a confidence badge, for every estimate.
4. **Time-aware Home:** greeting, tint and primary CTA shift by meal window (breakfast, lunch, snack, dinner). A contextual line such as "You usually log lunch around now" is derived from the user's log timestamps.
5. **Interactive Explainability:** `WhyThisRecommendation` shows a checklist that animates in. Each item links to the profile field behind it (for example tapping "within ₹200 budget" opens the budget editor).
6. **Desktop quick search:** `⌘/Ctrl + K` opens a food search palette.
7. **Judge helpers (Demo Mode only):** "Load sample week" (fills weekly report and streak) and "Simulate error" toggles in Settings → Developer.

## 12. CROSS-CUTTING RULES

**Loading states:** contextual and never a blank spinner. Use "Analyzing dish…", "Reading menu…", "Extracting items…", "Preparing nutrition estimate…", "Updating today's nutrition…", "Building recommendation…", "Reading report…", each with a matching animation (motes, scan-line, waveform) plus skeletons for lists and cards.

**Empty states:**
- No meals: "Nothing logged yet. Add your first meal to start building today's nutrition picture."
- No weekly data: "Log meals for a few days and your weekly patterns will appear here."
- No recommendation: "We need at least one logged meal or a selected nutrition goal before generating personalized suggestions."

**Error states (each with a recovery action):** image could not be processed (Try again / Retake photo), menu text not detected (Edit extracted item / Try another photo), food not recognized confidently (Search manually), no internet (Retry, offline banner), Firebase auth error, file too large, unsupported format, backend unavailable placeholder.

**Copy rules (strict)**
- Never: "You have iron deficiency." Always: "Your estimated dietary iron intake appears below your selected target based on logged meals."
- Never: "Contains exactly 420 calories." Always a range: "Estimated 400–460 kcal."
- No diagnosis, no medical claims, no guilt, shame, fear or anxiety language. Tone is encouraging and factual.
- **Every recommendation must expose `WhyThisRecommendation`**, for example: ✓ Fits vegetarian preference · ✓ No declared peanut allergen · ✓ ₹140, within your ₹200 budget · ✓ ~16g protein · ✓ Protein is one of your lower nutrients today.
- Return-visit hooks come only from usefulness: daily insight ("You're closest to your calcium goal today."), contextual suggestion, weekly progress, streaks, changing "Did you know?" cards. No dark patterns.
